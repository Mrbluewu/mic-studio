## 技术约束

1. TapBuffer 写端运行在 WASAPI 渲染回调中，必须保持有界、非阻塞且无运行期分配；双缓冲不得在未解决读者跨发布周期时单独视为正确方案。
2. VST2 `audioMasterAutomate` 可能从插件处理回调栈触发，不能假设只有一个生产者。若采用“每参数最新值”语义，须验证 ID/值原子一致性及 lock-free 性；若保留每次事件，则使用有界 MPSC 并定义溢出策略。
3. VST3 `IComponentHandler::performEdit` 按 SDK 合约来自 UI 线程，但 UI -> process 是另一方向，需独立建立线程安全传递；不得把 SDK `ParameterChangeTransfer` 未经确认当作跨线程队列。
4. 插件卸载、链重建与回调/消费方生命周期必须同步考虑，避免缓存参数表或 handler 在插件销毁后被访问。
5. 代码实施前检查工作树，保留所有既有和用户修改；本批不做版本递增、CHANGELOG 发布记录、提交或打包。

## 修复结果与证据

### H-1 TapBuffer 并发快照（已完成）

* 实施：`modules/engine/include/engine/tap_buffer.h` 的样本存储由 `std::vector<float>` 改为预分配的 `std::atomic<std::uint32_t>`（float 位模式），构造期一次性分配，写端不再触碰普通内存。
* 契约：写端为单写者，逐样本 `relaxed` 原子写，块结束时以 `release` 发布 `written_`；读端 `acquire` 读到起点后按"最近 `frames` 帧"尾部对齐复制（`take = min(frames, available)`），复制后再校验 `written_` 未变化。变化时返回 `false`，表示快照期间已被覆盖，调用方可丢弃该次结果。
* 边界：读者落后多个发布周期也不会产生 C++ 数据竞争（全部为原子访问）；不足 `frames` 时前补零；`frames == 0`、`dst == nullptr` 均为无操作或明确失败。
* 证据：`tests/concurrency_tests.cpp::test_tap_buffer`（空/短/满/多圈/环绕）与 `test_tap_concurrent`（20 万块并发写、校验整数值与最终稳定块）通过。

### H-2 插件参数回调有界化（已完成）

* 新增 `modules/dsp_core/include/dsp_core/bounded_parameter_queue.h`：定容量、无锁、无运行期分配的多生产者/单消费者队列，采用序列表位算法；`Capacity` 为 2 的幂，`try_push` 最多 8 次 CAS 后放弃，`try_pop` 单次判定，均无数据相关长自旋。
* VST2：`audioMasterAutomate` → `record_parameter_change` 不再 `lock_guard + push_back`，改为 `try_push`（容量 2048），任意线程可调用；`take_parameter_changes` 用 `try_pop` 组装返回 vector（该 vector 分配只发生在 UI 线程）。
* VST3：`HostComponentHandler::performEdit` 同样改为 `try_push`（容量 2048），删除原互斥锁与 `vector` 缓存及 `clear_changes`。
* 满载策略：丢弃新到事件并返回 `false`，不等待、不扩容、不覆盖已入队事件。

### H-3 VST3 UI→process 参数传递（已完成）

* 移除跨线程共享的 SDK `ParameterChangeTransfer`。`Vst3Slot::set_parameter` 只入队；`Vst3Slot::process` 在音频线程内独占写入本线程的 `ParameterChanges`（`in_changes`），参数点偏移 0，块末 `clearQueue`，UI 线程不再触碰 `controller->setParamNormalized`。
* 引擎级传递：`AudioEngine::set_plugin_parameter` 把 `(vst3 标志, id, 归一化值)` 打包为 `PluginParameterCommand`（单个 `uint64`）入队（容量 256），音频回调在每块 `chain.process` 之前 drain，且每块最多取 `capacity()` 条，保证单块工作量有上界。
* 生命周期：UI 侧 API（`plugin_parameters`、`set_plugin_parameter`、`take_plugin_parameter_changes`、`plugin_has_editor`、`open/close_plugin_editor`、`plugin_editor_idle`、`plugin_editor_size`）统一持既有 `std::recursive_mutex pipeline_mutex`；`start_pipeline`/`stop_pipeline` 持同一把锁，并在重建链之前先停流（`render.stop()`/`capture.stop()` 会 join 音频线程），因此 UI 不会访问已析构的 slot。音频回调不获取该锁。

### 实时路径复核

* 渲染回调内：`ring.read`、`raw_tap/processed_tap.write`、降噪 `process`、参数队列 drain（有界）、`chain.process`、重采样与桥接；`Chain::process` 仅为按序调用各级 `process` 的向量遍历，无分配、无锁。
* 未引入日志、字符串、`std::function` 拷贝或异常路径。
