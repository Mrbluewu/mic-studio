# 第三批实施计划

## Context

第三批聚焦可维护性：在稳定现有工程规范的基础上，将格式与静态分析纳入 CI；梳理 WASAPI 会话生命周期抽象；按启动阶段拆分 `micstudio/main.cpp`。已知原审查路线为 P1-1 → P1-3 → P1-4 → P2-4/P2-6，但本地仓库未找到审查报告，P2-4/P2-6 的具体定义未知。用户选择先按已知范围推进，并要求 CI 同时执行 clang-format 与 clang-tidy。

## Scope and approach

### 1. P1-1：规范与 CI 门禁

- 先检查 `.editorconfig`、`.gitattributes`、`.clang-format`、`.clang-tidy` 和根 `CMakeLists.txt` 的现有内容与实际工具链，不全盘重写已有规范。
- 保持 MSVC `/W4 /WX`，它已由项目构建配置启用。
- 在 `.github/workflows/build.yml` 增加格式检查和 clang-tidy 检查步骤；检查范围排除 `build/`、`third_party/` 等生成或外部代码。
- clang-tidy 当前配置标注为仅警告。首次启用 CI 检查时，先采集既有告警，修复本项目范围内可确认的问题；若需要抑制，使用定点配置并说明理由，不降低 `/WX`。
- 仅在发现配置缺项或工具运行所需配置不完整时，调整五个规范入口中的对应文件。

### 2. P1-3：WASAPI 会话抽象

- 以现有 `modules/audio_io/src/wasapi_session.h/.cpp` 的 `WasapiSession` 为基础，核对 open/start/stop、失败清理、重复 stop 和线程退出的契约。
- 保持 `capture_stream.cpp` 与 `render_stream.cpp` 中方向专属的 WASAPI 数据循环分离，不将 capture/render 缓冲行为合并成通用循环。
- 仅在能减少真实重复且不模糊方向差异时整理公共状态或统计映射；保持公开 `CaptureStream` / `RenderStream` API 不变。

### 3. P1-4：拆分 Mic Studio 启动入口

- 保留 `wWinMain` 作为进程入口和启动顺序编排点。
- 以现有 `app.h`、`app_ui.cpp`、`app_window.cpp`、`app_plugins.cpp` 的组织方式为参照，将 `main.cpp` 中具有清晰生命周期边界的命令行解析、单实例处理、运行时准备、设备/引擎启动、窗口/托盘初始化和消息循环/退出清理拆成少量内部函数或源文件。
- 不改变启动顺序、退出码、设备恢复、单实例唤醒及 UI 行为；不在本项顺带重构窗口消息处理或全局状态模型。
- 同步更新 `apps/micstudio/CMakeLists.txt` 的源文件列表（仅新增源文件时）。

### 4. P2-4 / P2-6

- 暂不猜测或实施。找到原审查报告并确认两条的原文、优先级和验收标准后，另行补入计划；本次已知范围先完成 P1-1、P1-3、P1-4。

## Verification

1. 验证 CI 使用的 clang-format 与 clang-tidy 版本可安装、命令可执行，并对本项目源文件执行检查。
2. 运行 VST3 OFF 配置：
   - `cmake -S . -B build -DMS_ENABLE_VST3=OFF`
   - `cmake --build build --config Release --parallel`
   - `ctest --test-dir build -C Release --output-on-failure`
3. 保持当前已有 VST3 ON 构建路径可用时，重复构建和测试，确保可选依赖配置没有回归。
4. WASAPI 方向分别进行真实设备启动、停止、重复停止、端点缺失/初始化失败验证；检查无挂起线程和设备资源泄漏。
5. GUI 验证 `--show`、`--exit-after`、启动最小化、第二实例唤醒、托盘退出、默认输入恢复及启动失败清理。
6. 检查改动 diff，确认格式变更未吞并无关文件或大面积重排；同步更新文档变更跟踪表。
